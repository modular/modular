Mojo installs exactly like a Python or Conda package on
macOS and Linux (see the [system requirements](/docs/requirements/)).

<ConditionalVersionDocs version="nightly">

<Tabs groupId="install">
<TabItem value="uv" label="uv">

1. If needed, install `uv`:

   ```sh
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. Install Mojo:

   ```sh
   uv pip install mojo \
     --index https://whl.modular.com/nightly/simple/ \
     --prerelease allow
   ```

   Or create a project and install Mojo:

   ```sh
   uv init hello-world
   cd hello-world
   uv add mojo \
       --index https://whl.modular.com/nightly/simple/ \
       --prerelease allow
   ```

</TabItem>
<TabItem value="pixi" label="pixi">

1. If needed, install `pixi`:

    ```sh
    curl -fsSL https://pixi.sh/install.sh | sh
    ```

2. Create a project and install Mojo:

   ```sh
   pixi init hello-world \
     -c https://conda.modular.com/max-nightly/ -c conda-forge
   cd hello-world
   pixi add mojo
   ```

</TabItem>
</Tabs>

These commands install the nightly build, which isn't complete and might have new bugs.
If you instead want the stable build, <Link href="/install/">switch to the stable
docs</Link>.

## What are uv, pixi, and conda?

Mojo isn't a Python package, but it's *distributed* as Python and Conda
packages. The Mojo toolchain—the compiler, standard library, debugger, and
language server—consists of large native binaries with their own
dependencies, and it includes a Python package for [Python
interoperability](/docs/manual/python/). Instead of building a bespoke
installer, Modular publishes `mojo` to standard package repositories (PyPI
and a Conda channel), so you can install it with the same tools you might
already use for other software and combine Mojo with other packages in one
reproducible environment.

Any Python or Conda package manager can install Mojo. Here's an overview of
the most common tools:

- [**pixi**](https://pixi.sh/latest/) is a package and environment manager
  for the Conda ecosystem. Each project gets an isolated environment defined
  by a `pixi.toml` manifest and locked to exact versions by a `pixi.lock`
  file, so installs are reproducible across machines. Conda packages can
  contain anything—not just Python code—so pixi can also manage compilers,
  CUDA libraries, and other native dependencies (and it can install packages
  from PyPI too). We recommend pixi for most Mojo projects; to learn more,
  see [Pixi basics](/docs/pixi/).

- [**uv**](https://docs.astral.sh/uv/) is a fast Python package and project
  manager. It installs `mojo` from PyPI into a Python virtual environment,
  which makes it a good fit if you already work in Python and want to add
  Mojo to your project. Because uv manages Python packages only, use pixi or
  conda if you need non-Python dependencies (such as GPU libraries) managed
  in the same environment.

- [**conda**](https://docs.conda.io/) is the long-standing package and
  environment manager of the Conda ecosystem (Anaconda, miniconda, and
  miniforge). Modular publishes `mojo` as a Conda package, so conda—or
  compatible tools such as mamba—can install it from Modular's Conda channel.
  Pixi installs these same Conda packages, but adds project manifests,
  lockfiles, and faster dependency resolution.

- [**pip**](https://pip.pypa.io/) also works: because `mojo` is on PyPI,
  running `pip install mojo` in a virtual environment installs the stable
  build. Pip is the lowest-common-denominator option; uv installs the same
  PyPI packages with faster resolution and project management.

No matter which tool you choose, you get the same `mojo` package with the
same `mojo` CLI and toolchain. The tools differ only in how they create and
manage the environment around it:

| Tool    | Package source | Lockfile          | Non-Python deps | Good fit when                                                 |
|---------|----------------|-------------------|-----------------|---------------------------------------------------------------|
| `pixi`  | Conda + PyPI   | `pixi.lock`       | Yes             | You want reproducible, project-scoped environments            |
| `uv`    | PyPI           | `uv.lock`         | No              | You already work in Python and want fast installs             |
| `conda` | Conda          | Environment files | Yes             | Your team already uses conda                                  |
| `pip`   | PyPI           | No                | No              | You want a quick install into an existing virtual environment |

## Get the VS Code extension

For syntax highlighting, code completion, and debugging support, install the
Mojo extension from:

- [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=modular-mojotools.vscode-mojo)
- [Open VSX Registry](https://open-vsx.org/extension/modular-mojotools/vscode-mojo)

## Get Mojo skills

Mojo agent skills keep your AI coding assistants aligned with the latest
language updates and best practices.

Install with:

```sh
npx skills add modular/skills
```
