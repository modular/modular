# debuglib

The purpose of this library is facilitate using LLDB in Python scripts for
Modular.

## SB API

It's worth mentioning that LLDB offers an object oriented Python API called
`LLDB Scripting Bridge`. Documentation is non-existent, so refer to the actual
`SB` classes for further information, e.g.

- third-party/llvm-project/lldb/include/lldb/API/SBDebugger.h
- third-party/llvm-project/lldb/include/lldb/API/SBTarget.h
- third-party/llvm-project/lldb/include/lldb/API/SBProcess.h
- third-party/llvm-project/lldb/include/lldb/API/SBFrame.h
- third-party/llvm-project/lldb/include/lldb/API/SBValue.h
- third-party/llvm-project/lldb/include/lldb/API/SBType.h

## Basic usage

The main entry point is `modular.utils.debuglib.get_debugger`, which is a
function that returns a correctly configured singleton `SBDebugger` instance.
From it, you can create a `SBTarget` which represents a program to be debugged.

The easiest way to represent Mojo sources files and compile them is to use the
`modular.utils.debuglib.sources` module. Once you have your binary prepared for
debugging, you can use the utility `modular.utils.debuglib.debugger.run_target`
to start debugging it.

## StopContext

Whenever you want to interact with the debuggee, you need to have it stopped
first. The `StopContext` class is returned by `debugger.run_target` and contains
the main elements you need to interact with the debuggee, e.g. target, frame,
thread, etc. It also offers some stepping functionalities, which return a fresh
`StopContext` after the stepping is done.

## lldbtypes

LLDB's scripting bridge is based on a module called `lldb` that is loaded at
runtime by `debuglib`. Because of this, type information is not available for
LSPs. As a workaround for getting some basic LSP support, `debuglib` includes a
module called `lldbtypes` which contains type definitions of every object in the
`lldb` module. It will greatly help you with autocompletion support and basic
type checking when writing your scripts.

The `lldbtypes.py` file was autogenerated using `stubgen`, and, as such, it
doesn't include argument types nor return types. Please complete these types as
you use the functions and classes in `lldbtypes`. That will be beneficial to
future devs.

### Changes in the SB API lldbtypes

The `SB API` doesn't change often, and it's incremental-only for backward
compatibility. In the rare event in which you need more type definitions, just
copy the required definitions from

`.derived/third-party/llvm-project/build-release/lib/python3.XX/site-packages/lldb/__init__.py`

into `lldbtypes.py`.
