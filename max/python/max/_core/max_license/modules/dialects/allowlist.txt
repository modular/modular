# Records bound into `max._core.dialects`.
#
# Every op, attribute, type, interface, enum and pass a dialect declares could be
# bound, but each one costs real binary size in the `_core` extension, and only a
# fraction is ever named from Python. This file is that fraction: the generator
# (`internal/mlir_nanobind/tblgen`) binds these TableGen records and skips the
# rest. Skipping is not a hard boundary — an unbound attribute or type still
# reaches Python, as the base `Attribute`, `Type` or `OpState` rather than as its
# own class.
#
# Names are TableGen record names; the trailing comment gives the Python name.
# Adding an op to `max.graph` means adding it here too. Dropping a line that
# something still uses turns an
# attribute access into an `AttributeError` and quietly weakens any `isinstance`
# against it, so leave a line alone unless the last use is gone.
#
# "Uses" is wider than "names". `_set_output_param_decls` in `max/graph/graph.py`
# reaches ops by duck-typing rather than by name, so every op implementing
# ParamDeclarationInterface is listed whether or not Python spells it out —
# unbound, such an op loses the accessor, the pass skips it, and the graph
# fails to compile against an undeclared parameter much later on.
#
# The list has to name everything the bindings need, including what one entry
# refers to from another — generation fails, listing the names, when it doesn't.
# It can't be inferred at build time: generation runs once per TableGen file, and
# a reference across dialects is only visible from the referring side.
#
# A handful of records cannot be bound at all, so wanting one is not enough —
# adding these breaks the build rather than the list, and needs the generator
# taught first:
#
#   Builtin_DenseResourceElementsAttr   AsmResourceBlob is not handled
#   Builtin_SparseElementsAttr          same, via its resource-backed storage
#   OpaqueLoc                           constructors are templatized
#   KGEN_ParamConstantOp                BytecodeOpInterface takes internal
#                                       payload types
#   KGEN_ParamMaterializeOp             uses `Res<AnyType, " ", [MemAlloc]>`,
#                                       which the generator doesn't implement
#   KGEN_NoneAttr                       NoneAttr::get resists binding
#   KGEN_CallOp                         CallOp::setCalleeAttr resists binding
#   KGEN_BindParamsAttr                 these take the internal evaluation
#   ContextuallyEvaluatedAttrInterface  context type
#   ContextuallyEvaluatedTypeInterface
#   DeclRefAttrInterface
#   StructTypeInterface
#   RMO_ConcatOp                        OptionalAttr, which tblgen generates as
#   RMO_MOTransferOp                    a nullable mlir::Attribute where these
#                                       bindings generate std::optional
