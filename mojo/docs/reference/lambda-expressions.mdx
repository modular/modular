A *lambda* is an anonymous, single-expression function. It has no name,
only one body expression, and no `return` statement. Once compiled, it's
equivalent to a standard but restricted function:

```mojo
def main():
    var inc = lambda (x: Int) {} -> Int: x + 1  # No `return`
    print(inc(4))  # 5
```

This is just like declaring:

```mojo
def inc(x: Int) {} -> Int:
    return x + 1

print(inc(4))  # 5
```

Capture lists are optional. Lambda expressions can be used as function
pointers and closures.

:::caution
Lambda expressions are under active development.

At this time, return-type inference isn't implemented.

Omitting the return type defaults it to `None`. Mojo won't infer the return
type from the body or the use site.

The rules on this page describe Mojo's current behavior.
:::

## Syntax

Lambda expressions use a precise and compact syntax.

Most parts are optional, depending
on what the lambda captures, accepts, and returns. You must include the
`lambda` keyword, the colon, and a body expression:

```text
lambda [[parameter-list]] [(argument-list)] [effects]
       [{capture-list}] [-> ResultType] : expression
```

The simplest, empty lambda is as follows. It takes no arguments, captures
nothing, and returns `None`:

```text
lambda: None
```

Lambda elements follow the same order as functions:

```mojo
def main():
    # Fully explicit.
    var a = lambda (x: Int) {} -> Int: x + 1

    # Capture list elided.
    var b = lambda (x: Int) -> Int: x * 2

    # Return type elided, defaults to `None`.
    var list: List[Int] = [1]
    var c = lambda (x: Int) {mut list}: list.append(x)

    # Everything elided: no arguments, no captures, `None` result.
    var d = lambda {mut list}: list.append(0)
    print(a(4), b(4))  # 5 8
```

## Arguments

Each argument must be typed and appear in the parenthesized argument list.
Types can be concrete (`String`) or parameterized (`T`, `Self.U`):

```mojo
# Concrete argument
var hello = lambda (x: String) {} -> String: "Hello, " + x

# Parameterized argument
var inc = lambda [T: Intable](x: T) -> Int: Int(x) + 1
```

Omit argument lists for lambdas that don't take arguments.

### Argument conventions

Arguments use the same conventions as functions. The default is `imm` for
an immutable reference:

```mojo
def main():
    var read_arg = lambda (x: Int) {} -> Int: x + 1
    # AKA: var read_arg = lambda (imm x: Int) {} -> Int: x + 1
    var own_arg = lambda (var x: Int) {} -> Int: x + 1
    var mut_arg = lambda (mut x: Int) {}: x.__iadd__(1)

    var list: List[Int] = [1, 2, 3]
    mut_arg(list[0])
    print(list)  # [2, 2, 3]
```

### Variadic arguments

Lambda expressions support `*args` and `**kwargs`, separately or together.
`**kwargs` packs into an `OwnedKwargsDict`, so declare it with `var`:

```mojo
def main():
    var count = lambda (*args: Int) {} -> Int: len(args)
    var named = lambda (var **kwargs: Int) {} -> Int: len(kwargs)
    print(count(10, 20, 30))  # 3
    print(named(a=1, b=2))    # 2
```

## Return types

When omitted, return types default to `None`:

```mojo
lambda: 5                     # Error: can't convert IntLiteral to None
lambda (x: Int) {}: x + 1     # Error: can't convert Int to None
```

## Lambda closures and capture lists

Some lambda expressions are *closures*. A closure carries state from its
enclosing scope, or binds the parameters it declares at each call site.

Lambda capture lists use the same
[conventions](/docs/reference/closure-declarations/#capture-conventions) as
nested `def` closures, namely `imm`, `mut`, `ref`, `var`, plus copyable and
movable.

A lambda becomes a closure under these circumstances:

- The lambda body references a value from the enclosing scope.

  ```mojo
  var z = 10
  var f = lambda (x: Int) -> Int: x + z  # `z` is captured
  print(f(5))  # 15
  ```

  In the absence of an explicit capture list, the default capture
  convention used here is an immutable reference (`imm`).

- The lambda body uses an explicit capture convention.

  ```mojo
  var list: List[Int] = [1, 2, 3]
  var f = lambda (x: Int) {mut list}: list.append(x)  # `list` is captured
  f(10)
  print(list)  # [1, 2, 3, 10]
  ```

  Using `{mut}` produces the same result, but `{mut list}` is more precise.
  It limits captures to `list`. `{mut}` captures every outer value used in
  the body. Explicitly naming captures turns accidental references into
  errors instead of silent captures.

- The lambda declares a parameter list.

  ```mojo
  # N is lambda-owned, bound at each call
  var f = lambda [N: Int](x: Int) {} -> Int: x + N
  print(f[5](3))  # 8
  ```

Parameters owned by the surrounding scope are compile-time substituted,
not captured:

```mojo
def total_as_ints[T: Intable & Copyable](args: List[T]) -> Int:
    var to_int: def(v: T) thin -> Int = lambda (v: T) -> Int: Int(v)
    var total = 0
    for ref a in args:
        total += to_int(a)
    return total

def main():
    print(total_as_ints([1.5, 2.5, 3.9]))  # 6
```

An empty capture list (`{}`) means "capture nothing." It excludes the
default `imm` convention, so using a variable from an enclosing scope is
an error:

```mojo
var z = 10
var f = lambda (x: Int) {} -> Int: x + z  # Error: z isn't captured
```

Any capture convention makes a lambda a closure even when it captures
nothing. `lambda (x: Int) {imm} -> Int: x + 1` is a closure. The same
lambda with the capture list omitted is thin.

## Thin lambdas {#thin}

A lambda that isn't a closure is `thin`. To be thin, a lambda captures
nothing, uses no explicit capture conventions, and doesn't declare its
own parameters. In return, it unlocks the following capabilities. A
thin lambda can be:

- Used as a thin function pointer, including `abi("C")` callbacks.
- Bound to a symbol with `comptime`.
- Used as a thin function-type parameter.
- Returned from a function.
- Stored in a struct field.
- Used as a default argument or parameter value.

Thin matters when a lambda callable must outlive the scope that created it
or it is needed at compile-time.

### C ABI boundaries

Thin lambdas can cross C ABI boundaries because they don't carry
runtime state:

```mojo
var fp = lambda (a: Int32, b: Int32) abi("C") -> Int32: a + b
print(fp(1, 2))  # 3
```

The `abi("C")` effect must appear on the lambda declaration. It's not
enough to type the variable. If you choose to use explicit typing, the type
must *also* carry the `abi("C")` effect.

### Runtime and compile-time

You can call any lambda directly. You can pass any lambda as a runtime
argument to higher-order functions with function-shaped infer-only
parameter types:

```mojo
def hof[T: def(x: Int) -> Int, //](f: T): # ...
```

Compile-time parameters are different. Unless a parameter is explicitly
typed as `thin`, you can't pass lambdas. When it is, the lambda must be
thin.

Thin lambdas can be executed at compile time, with the result assigned to a
comptime name:

```mojo
def main():
    comptime whole = (lambda (x: Int) {} -> Int: x * 2)(21)
    print(whole)  # 42
```

## Effects

Place lambda effects after the argument list and before the capture list:

```mojo
def apply_raising(f: def(x: Int) raises thin -> Int, arg: Int) raises
    -> Int:
    return f(arg)

def main() raises:
    print(apply_raising(lambda (x: Int) raises -> Int: x + 1, 2))  # 3
```

Every lambda body is a single expression and can't contain a `raise`
statement. Lambdas only raise by calling something else that raises.
Declaring `raises` allows the lambda to propagate exceptions, not
raise them.

## Nesting

Each lambda body can contain another lambda expression. The inner one
captures the outer one's arguments through its own capture list, and
references the outer one's parameters directly:

```mojo
def main():
    var f = lambda (x: Int) {} -> Int: (
        lambda (y: Int) {imm x} -> Int: y + x
    )(3)
    print(f(6))  # 9
```

## Formatting

`mojo format` adds a space after `lambda` before any argument list or
parameter list opener. A lambda reads as `lambda (x: Int) -> Int: e`, not
`lambda(x: Int) -> Int: e`.

Short lambdas stay on one line; one that exceeds the line width wraps
using standard expression-splitting rules.

## Restrictions

Lambda expressions have the following restrictions:

- **Single expression**: The body is one expression. There's no
  `return`, no statement body, and no multi-statement form.
- **No return-type inference**: An omitted return type is `None`, not a
  solved type.
- **Arguments need types**: There's no argument-type inference from the
  use site.
- **No escape**: Lambda closures can't outlive their enclosing scope, the
  same restriction `def` closures carry.
- **No `thin` in the signature**: Thin effects apply to function *types*,
  not to a lambda declaration.

## Errors

| Compiler complaint                            | Trigger                                         |
|-----------------------------------------------|-------------------------------------------------|
| Unparenthesized lambda arguments              | Python's `lambda x, y: ...`                     |
| Argument type must be specified               | A parenthesized but untyped argument            |
| Can't convert value to `None` in return value | A non-`None` body with the return type omitted  |
| Could not infer capture convention            | A free variable under an explicit `{}`          |
| Mutating method on an immutable value         | Mutation through an `imm` capture               |
| Capturing lambda in comptime initializer      | A lambda closure bound to a `comptime`          |
| Capturing lambda in type parameter            | A lambda closure passed as a parameter          |
| Capturing lambda in default parameter         | A lambda closure as a parameter's default value |
| Can't implicitly convert to a `thin` type     | A lambda closure passed to a `thin` parameter   |
